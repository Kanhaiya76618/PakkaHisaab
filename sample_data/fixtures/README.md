# Intake fixtures

## Vision

`vision_invoice.json` — **ground-truthed against a real photograph.**
`sample_data/mehta_inv_231.jpg` is a photograph of a printed invoice
(MEHTA KIRANA SHOP, INV-231, 12/07/2026, ₹4,800), staged as SPEC §11 permits. Every field
in the fixture was read off that photograph by hand. The *extraction* is still a
PLACEHOLDER — no live vision call was made, because this environment has no usable
`OPENAI_API_KEY` — but because the source document is real, re-recording this fixture
against `gpt-4o` is a genuine OCR accuracy measurement rather than a round trip through
synthetic text. Do that first when a key is available, then diff every field against
`../GROUND_TRUTH.md`.

`vision_khaata.json` — **PLACEHOLDER** against a generated image. `khaata_page_1.jpg` is
rendered by `sample_data/generate.py` with the bundled Kalam font, and this fixture is
aligned to the same constants, so it is regression-tested against ground truth but proves
nothing about real handwriting OCR. Replacing `khaata_page_1.jpg` with a photograph of a
real handwritten khaata page — and re-recording this fixture against it — is the highest
-value fixture upgrade left in the project.

## Speech

`transcribe_indic.json` (Sarvam `saaras:v3`), `transcribe_hi.json` (OpenAI `whisper-1`),
`tts_indic.json` (Sarvam `bulbul:v3`), `tts_hi.json` (OpenAI `tts-1`), and
`classify_txn.json` — all **PLACEHOLDER**, in each provider's own documented response shape
(docs.sarvam.ai, read 2026-07-30). No `SARVAM_API_KEY` exists in this environment and no
live call was made. `sample_data/voice_ramesh.m4a` from SPEC §11 does not exist yet, so
there is no real audio to transcribe; the tests exercise the path with synthetic bytes.
Each file states this in its own `_provenance` field.

The Sarvam-vs-Whisper transcripts are the *inputs* to the eval comparison, not its result:
`backend/evals/runner.py` runs the real amount extractor over both at request time, so the
pass/fail is computed even though the transcripts are placeholders.

## Deterministic

`expected_m3.json` and `golden_m3.json` are generated by `scripts/generate_golden.py` from
committed seed inputs. Regenerate them whenever engine output shape changes; never hand-edit.

`risk_history.json` holds the demo store's pre-July receipts and its declared turnover —
seeded data, documented in `engine/risk.py`, never invented at runtime.
